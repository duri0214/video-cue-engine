# GUI デザインルール

## 画面構成

- この GUI は `eframe/egui` のスクロール可能なメイン画面で、操作は `src/gui/app.rs`、色・全体スタイル・パネルは `src/gui/theme.rs` に置く。
- 操作は「01 入力フォルダ」「02 出力フォルダ」「03 Django へ送信」「一括解析と進捗」「動画ごとの結果」の順で理解できるようにする。変更理由がない限り、この順序と各操作の役割を保つ。
- 入力フォルダは直下の MP4 件数と再読み込み、出力フォルダは選択中の保存先、Django 送信は初期オフの任意設定を示す。ローカル成果物が保存されることも送信設定の近くで説明する。
- フォルダの指定には OS のフォルダ選択ダイアログを使い、選択後はパスを表示する。パスを自由入力させず、長いパスは折り返して読めるようにする。
- 背景、パネル、境界線、文字、アクセント、エラー色は `theme.rs` の定義を基準にする。既存の `theme::panel()` と egui の標準ウィジェットを使い、画面ごとに似た色や寸法を増やさない。
- 同じ表示や操作が複数箇所で必要になった場合は、使う場所を確認してから `theme.rs` に共通化する。現在ない共通部品や将来用の抽象化は先回りして作らない。
- ボタンや説明には利用者が次に行う操作を記し、内部の型名や処理名だけで案内しない。無効な操作は egui の実際の無効状態で示す。

## 状態とフィードバック

- 状態数に合う表示を使い、色だけを状態の手掛かりにしない。2状態は「未選択／選択済み」「オフ／オン」のように一つの場所で両方を判別できる文言を使う。3状態は入力設定の「未設定／エラー／解析可能」のように、各状態を個別に読める表示にする。
- 動画行の状態は「待機」「解析中」「完了」「失敗」「送信中」「送信済み」「再送確認済み」「送信失敗」のように区別し、成功・失敗件数や進捗表示と食い違わせない。
- 一括解析の開始後は回転表示と現在の処理を表す文言を出し、処理終了後に消す。全体の進捗と動画ごとの行状態はそれぞれの範囲を示し、同じ情報を通知として重ねない。
- 状態表示でエラーを知らせる場合、新しい失敗が起きたときだけ該当表示を一瞬白からエラー色へ変え、短く一度だけ揺らす。演出後は動きを止め、失敗状態、理由、次に取れる操作を読める形で残す。色や動きだけで失敗を伝えない。
- 解析や送信の失敗理由は該当する動画行の近くに置き、再送できる場合は「ローカル成果物から再送」のように次の操作を示す。全体の件数表示は集計に使い、同じエラー全文を全体と動画行へ重複して表示しない。
- 「一括解析を開始」は入力の解析準備と出力先の両方が整った場合だけ有効にする。選択済みや ON の強調は、利用者が実際に選択・有効化した後だけ表示する。

## 入力と操作

- 同じ目的に対する入力方法を追加する場合は同じ階層の選択肢として示し、選択した方法に必要な入力だけを結び付ける。入力やチェックボックスのラベルから対象と結果が分かるようにする。
- フォームを追加する場合は、縦に並ぶラベルの位置と入力・選択欄の左端を揃える。同じ階層のボタンを縦に並べる場合も幅と左右の端を揃え、文字が収まる幅とウィンドウ幅を考慮する。
- 独自のペインやダイアログに閉じる操作を設ける場合は、右上に `×` を置き、ツールチップで「閉じる」と示す。現在のメイン画面や OS のフォルダ選択ダイアログに、不要な閉じる操作を追加しない。

## 目検

- GUI の変更を含む PR では、実行場所と前提、画面上の正確なラベル、入力値、操作順、期待結果を使って確認手順を書く。
- 同じ起動や入力を繰り返さず、1回の結果を使って後続の確認を行う。別の状態や入力経路を確かめる場合だけ再実行する。
- 既存の `[x]` を `[ ]` に戻さない。未実施の確認は新しい `[ ]` として追加し、実際に確認した項目だけ `[x]` にする。
